# Project notes

This repository is the live ASCII Stage 1 site for Livi Cracknell / Livicee. GitHub `main` deploys to GitHub Pages.

- Authority: `PRODUCT.md`, the current token-bearing `DESIGN.md` . The build follows the code-led ASCII direction. Mockups are not layout authority. Livi's 11 October feedback restores the Pixel Experience row structure and About line within the current ASCII shell. The screen treatment retains subtle depth only at the aperture and flush controls. Header/footer use independent #151417 bars and one-pixel seams against the #18171a rail; the phone dock shares that bar surface. Earlier layout suggestions were rough input, not a literal specification. Keep its rationale in DESIGN.md. The header DOM is availability line (`.header-status`, the identity's `status`, or the copyright line where it is empty), full-name mode switch, search, with the 260px switch placed at the left on desktop and the availability line in the middle; the footer holds the sample note (left), a plain muted copyright line (middle, `.footer-copy`) and, at the right, `.footer-actions`: a `Copy email` button (`data-copy`) beside the contact link; a pink-marked label in the middle competed with the header's availability line and repeated what the switch and header icon already say, so do not add one back; `.navigation` contains only links. Breadcrumbs remain the first child of `#view` on every route, empty and hidden off records, preserving positional reconciliation. Desktop uses a 192px rail, 56px header, 44px footer, and the reading area runs flush to the window edge so its scrollbar sits there (no right return). the 44px switch (260px on desktop, up to 300px on phones) uses switchLabel for both visible and accessible names (Livi Cracknell / DJ Livicee). Search is 212px at the right, collapsing to 44px at <=960px; 761–960px focused width is min(240px,50vw - 180px). At 761–1100px the longer supplied status wraps between the switch and search; focused compact search at 761–960px hides the status until blur. On phones the header availability line hides and the same full-name switch uses min(300px,100vw - 80px) with 12px labels beside the 44px search target. Escape exits compact search and restores selected-identity focus without clearing the query. Phones use a 56px header and one 64px dock plus safe area, with the standalone footer hidden and Contact retained in navigation/page actions.
- Chrome details: the availability line in the header carries a pulsing pink dot; the two identities are one 44px segmented switch whose raised pill slides on `.workspace[data-dataset]` (keep the shell node persistent so it animates); the rail's items are 48px rows with 28px icon tiles (14px glyph plus 7px padding on each side) (the active tile turns pink) and between the top options and the foot group sits a hairline, then a real ASCII field drawn on a canvas by `railField.ts` (markup in `railArt.ts`, layout in `rail.css`) that fills the whole gap down to the next hairline. It is one plain, shared sweep for both identities: the portrait's own 6x9 cell, glyph ramp and pink, a dot lattice with a soft wave travelling down it (about 6.8s per sweep). The designer asked for ASCII here and rejected drawn objects (laptop, books, record and similar) in every form tried, so keep it object-free. It is hidden on phones and under 560px tall, a single still frame for reduced motion, and paused when off screen. The foot group (Contact, and LinkedIn on Content or SoundCloud and Instagram on Livicee, from `site.json`, using HTTPS provider-domain validation) is pinned to the foot of the rail above a hairline on desktop, while phones keep the plain dock and expose profile links on Contact; the switch track and the search box are drawn 36px tall (`::after` / `::before`) over 44px hit areas, so touch targets keep the 44px rule; above 900px wide an identity mark (a stacked-layers icon for Content, headphones for Livicee, both 22px line icons, drawn as background SVGs on `.topbar::before`/`::after` so the header DOM is unchanged) crossfades at the far left as a bare glyph (no tile or border, so it reads as a logo, not a button), centred over the rail's icon column; there is no icon library, every icon is a hand-written inline SVG in `html.ts` or a CSS background; search is a recessed field; ordinary action buttons and desktop navigation rows are square; recessed controls, mode buttons and icon tiles use 4px radii, cards 6px, and chips and entry media 3px. Only the header availability line carries the slowly pulsing pink dot via `data-status`, disabled under reduced motion; the footer copyright is plain.
- Stack: Vite, TypeScript, semantic DOM and Canvas. Entry: `index.html` → `src/workspace/main.ts`. Preserve relative assets and hash routes for nested static hosting.
- Datasets: internal `production` / `sound`, public **Content** / **Livicee**, in one shared shell. `modeDestination()` preserves corresponding sections.
- Content: living copy is `src/content/*.json`. Types for those files are `src/content/schema.ts`. Lookups stay in `src/workspace/content.ts`; the record shape is `src/workspace/model.ts`. The public site has no editor. Edit these JSON files directly in GitHub on main; the existing Pages workflow publishes after build checks pass. README.md starts Livi's workflow, src/content/README.md covers edits and recovery, and DEVELOPER.md contains local setup. There are 30 sample records: 10 projects, 12 attached evidence records, 3 CV entries on Experience and 5 mixes. Only Projects and Mixes are record collections; retired categories redirect to them. A project's `tags` are its capabilities: the `tag` facet (`query.ts`, `search.ts`) filters Projects by them with counts through underlined capability links on project pages and native checkboxes in the single Filter dialog. Do not restore a duplicate quick-filter row. Content has five tabs (Overview, Projects, Experience, About, Contact); Livicee has four (Overview, Mixes, About, Contact). Naming trap: internal `work` means Projects/Mixes, while the public **Experience** tab is the CV page at `#/experience`, enabled by `cvLabel` in `site.json`. Each identity's desktop header availability uses `status` in `site.json`; empty uses copyright. Nonempty status also appears above the mobile Home title. Livi supplied the current professional status, `Currently: Implementation Success Manager @ Storyblok`; Contact uses neutral professional enquiry copy. Livicee retains `Available for Bookings`, with supplied SoundCloud and Instagram profiles and no YouTube channel yet. Every record stays `"sample": true` until a confirmed replacement is written into JSON. The only visible sample marker is the footer's "Sample collection" (`footerNote`); pages carry no disclaimers, page descriptions, how-to lines or repeated gateway links, so do not add them back. Never invent claims, likeness details or recordings, and remove the footer note when real content replaces the samples.
- UI: `views.ts` owns the shell; `pages.ts` overview/about/contact and the CV; `library.ts` collections and evidence; `html.ts` shared markup; `audio.ts` native audio, SoundCloud play controls and the click-to-load Mixcloud player; `player.ts`/`player.css` the persistent SoundCloud bar (a hidden official widget driven over postMessage, created on first play and kept outside the re-rendered shell so playback survives navigation); `embeds.ts` builds the only player URLs that may be framed. `viewState.ts`, `filterDialog.ts` and `dom.ts` preserve history, focus and native element state.
- Identity: `src/ascii/field.ts` draws the continuous glyph field from the two tonal `-source.png` assets. `src/workspace/identity.ts` integrates lifecycle and layout; `src/ascii/pointer.ts` owns elapsed-time pointer release. Preserve large drawing scale, reading shields, bounded motion, reduced motion, idle/hidden suspension and readable failure states. Waveform seeking is shielded; only primary presses react, and drags begun on controls or copyable text stay shielded through release. See `docs/ASCII-RENDERER.md`.
- Motion: `veil.ts` draws a decorative 560ms visible-text veil on identity changes. Never mutate semantic copy or block navigation. Keep the portrait position independent of route. Live reduced-motion changes also cancel active crate-reorder and Document/Model animations and clean up their temporary styles.
- Evidence previews: `evidencePreviews.ts` shows the evidence record's `artwork` image (16:9, cropped to fill; currently the shared placeholder `media/evidence-placeholder.png`) and, only when a record has no artwork, the diagram generated from its actual structured evidence, as it is: no character layer and nothing hidden behind a hover. Opened evidence remains semantic HTML.
- ASCII is the portrait's material (the identity field and the mode veil), plus the rail field described above. Mixes, evidence and any other media are drawn as clean vector shapes or shown as they are. `night.ts` draws Livicee's night charts and `waveform.ts` the measured waveforms, both as SVG; a waveform only ever comes from measured peaks for the actual attached recording.
- Visual rules: root font-size stays 100%; rem-based reading roles provide 18px body, 16px detail, 14px metadata/actions and 12px compact information at the default root. Share 32–44px page and 28–36px record headings; reserve shared 40–56px desktop display for Overview (32–44px on phones). Section headings are 22px (20px phone); list-item titles (project cards, mix rows and Livicee Overview mixes) are 20px with 16px summaries at every width. Interactive targets remain at least 44px. Keep row paint inside its hit target, text steady, and selected/focus states distinct. Use segmented view/order choices, underlined reference links, plain sample status and one native Filter dialog with scrolling facets between fixed header/footer. Collections lead with introduction, then one live count/Sample left and Clear/Filter right; index rows use supplied subtitles in 280px/240px columns above 960px. Mobile navigation uses 12px labels beneath 18px icons. The approved mobile Overview composition centers the existing 430px-wide portrait at a 14px top offset and reserves at most 340px above the text, contracting to preserve 200px reading space when available; both mobile Home routes show the portrait, while every other mobile route hides its portrait layers and removes the introduction gap, retaining the quiet lattice. Preserve the original source artwork, head registration and ASCII effect. Keep main heading tracking no tighter than -.035em, and the mobile **Home** label within equal navigation columns (five on Content, four on Livicee).
- Entries are cards, as a CMS lists content (`cards.ts`, `cards.css`): a thumbnail (the record's 16:9 `artwork` image from JSON, cropped to fill; projects share the placeholder `media/project-placeholder.png` and evidence `media/evidence-placeholder.png`; without artwork a project falls back to its evidence diagram from `evidencePreviews.ts`), a content-type tile, a mono uppercase field label, 20px title, 16px summary (inside the 22px section headings), with the thumbnail filling the card height on desktop and plain mono tags. Documents use unboxed facts, underlined capability links, a labelled story card and hairline-divided related rows. In the page body pink is reserved for the primary action, the current selection and Livicee's headline; badges, chevrons, tab underlines and ordinary links are neutral, and list waveforms stay dim until hovered, selected or playing. Project and evidence pages show their image full width at 16:9; mix covers stay square. Sans is what is read, mono is what the system labels. Keep the class names `project-row` and `overview-item` (contract tests match them); retain cards for project/mix entries and related records. Experience intentionally restores the Pixel version's numbered, date-first native disclosure rows separated by hairlines.
- Type system: two voices. Instrument Sans (400 body, 500 for action labels: nav, switch, buttons, links and toggles; 400 for the search input; 600 for titles) and Fragment Mono only for what the system reports (counts, field labels, chips, meta, breadcrumb, footer). Display is 600 at 1.05-1.08 line height and -.035em; body 18px at 1.55-1.6; mono caps labels +.08em. Both Overview headlines use Instrument Sans with the same size, weight and line rhythm; Livicee's second phrase stays pink.
- Title rhythm: measured from the title's baseline to the next line's cap height, every page title sits 30px above its subtext (16px between the boxes; 32-33px under the two large display headlines). The list toolbar (count and Filter) is 6px under the title box so its count lands on that same line; the Filter box is drawn 36px tall over its 44px hit area, like the header controls; the first card sits 24px under the toolbar. A title with no subtext (Experience) puts its first disclosure group 20px below. Measure with baselines and cap heights, not ink: descenders in 'Projects' versus 'Mixes' make the same CSS read differently.
- Fonts: self-hosted Instrument Sans and Fragment Mono, each with its OFL source licence. `vite.config.ts` emits both OFL licence files into production builds. The two `.woff2` files live in `src/assets/fonts/` and are preloaded in `index.html`. The `.ttf` sources in `assets-source/fonts/` are Instrument Sans (the variable font from google/fonts `ofl/instrumentsans`) and Fragment Mono; regenerate a `.woff2` with fontTools, `flavor = 'woff2'`, if a font changes.
- Verify relevant changes with `npm run check`, `node tests/evidence-previews.mjs` and `npm run build`; the bounded browser fixtures are described in `DEVELOPER.md`.
- Do not introduce simulated playback, editing or publishing controls on the public portfolio. Content editing uses GitHub directly; do not restore a local editor, launcher or content write/upload endpoints. Keep content validation in the build.

- Publishing: a push to `main` publishes the public website. Never push or merge to `main` without the site owner's explicit instruction for that change; work on a branch otherwise. Run `npm run build` before committing. Node.js 22.12+ within 22 (`.nvmrc`).
- Address: `siteUrl` in `site.json` drives the canonical link, link-preview tags, schema.org data, `robots.txt` and `sitemap.xml`. `searchTitle` and `searchDescription` in `site.json` supply the page title, meta and link-preview description, schema.org description and no-JavaScript fallback; `index.html` holds only `%SITE_*%` placeholders for them. It holds the placeholder `https://livi-cracknell.github.io/` until the owner sets their real address; do not change it or hosting without instruction. `HANDOVER.md` holds the setup, Pages and address steps.
